# Phase 7–10 visual reference

These original Casaura concepts were generated during implementation to establish the
approved information hierarchy, responsive intent, component density, and trust language
for the final four phases. They are reference artifacts, not production screenshots or
evidence of live provider data.

| Artifact | Purpose |
| --- | --- |
| `integrations-desktop.png` | Desktop RESO connection, mapping, sync, duplicate, and error operations |
| `integrations-mobile.png` | Mobile task order, metrics, mapping controls, and workspace navigation |
| `assistant-desktop.png` | Grounded search conversation, public results, citations, collections, and comparison tray |
| `assistant-mobile.png` | Mobile grounded-result cards, supporting disclosures, and fixed compare action |
| `billing-desktop.png` | Subscription, invoices, sponsored campaigns, entitlements, and policy disclosure |

The running implementation intentionally uses API-backed acceptance fixtures, so counts,
names, images, dates, and states differ from the illustrative concepts. Product-safety and
data-honesty rules take priority over literal copy: AI filters are proposed until confirmed,
unsupported transit/market claims are omitted, RESO credentials are never displayed,
Stripe automatic tax is described as provider-hosted behavior, and sponsored inventory is
always labeled and kept outside organic ranking.

The five-point implementation comparison and responsive decision ledger are maintained in
[fidelity-ledger.md](../../../design/fidelity-ledger.md).
